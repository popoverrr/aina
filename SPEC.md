# ТЗ: персональный сайт эксперта по коммерческой недвижимости (Алматы)

> **Как этим пользоваться.** Положи этот файл в пустую папку как `SPEC.md`, открой там Claude Code и дай команду:
>
> ```
> Прочитай SPEC.md целиком. Это техзадание на сайт. Реализуй его по этапам,
> начиная с «Этап 0». После каждого этапа останавливайся, показывай что сделано
> и жди подтверждения. Не переходи к следующему этапу без моего «ок».
> Не выдумывай функционал, которого нет в SPEC.md.
> ```
>
> Если хочешь всё за один проход — замени вторую часть на «Реализуй этапы 0–5 подряд, без остановок, в конце запусти сборку и покажи результат».
>
> **Заполни перед стартом:** все плейсхолдеры вида `{{ИМЯ}}` в разделе 2. Пока они не заполнены, Claude Code будет подставлять заглушки, и текст на сайте получится безликим.

## 0. Контекст проекта (для понимания решений, не для реализации)

Заказчик — риелтор по коммерческой недвижимости в Алматы. Работает внутри агентства, но продвигает **личный бренд**, а не бренд агентства. Специализация — стрит-ритейл в «золотом квадрате», офисы, земельные участки. Основной целевой клиент — инвестор, далее арендатор и собственник.

Сайта сейчас нет. Трафик придёт из Instagram, с офлайн-баннеров и наклеек на объектах (по QR-кодам), из таргетированной рекламы. Поисковый трафик на старте вторичен — по общим запросам выдачу держит krisha.kz.

**Из этого следуют три принципа, которым подчинено всё ТЗ:**

1. **Mobile-first буквально.** Не «адаптив», а проектирование от экрана 375px. Большая часть посетителей придёт из ленты соцсети с телефона.
2. **Сайт — доказательство, а не каталог.** Сначала человек должен поверить эксперту, потом смотреть объекты. Порядок блоков на главной именно такой.
3. **Каждая страница ведёт к одному действию.** Нет действия — нет страницы.

## 2. Переменные проекта — ЗАПОЛНИТЬ

Собери всё в `site.config.ts` и импортируй оттуда. Ни одной из этих строк не должно быть захардкожено в компонентах.

```ts
export const site = {
  agent: {
    fullName: "Айна {{ФАМИЛИЯ}}",
    shortName: "Айна",
    role: "Коммерческая недвижимость",
    tagline: "Помогаю заехать и зарабатывать",   // её собственная формулировка из шапки Instagram
    city: "Алматы",
    yearsInMarket: {{ЧИСЛО_ЛЕТ}},
    closedVolume: "{{ОБЪЁМ ЗАКРЫТЫХ СДЕЛОК, например «более 3 млрд ₸»}}",
    phone: "+7 701 085 77 17",
    whatsapp: "77010857717",
    telegram: "{{username}}",
    instagram: "ainona.17",
    email: "{{...}}",
  },
  site: {
    domain: "{{домен.kz}}",
    defaultLocale: "ru",
    locales: ["ru"],          // "kk" добавится на этапе 2
  },
  legal: {
    entity: "{{ИП / ТОО, БИН/ИИН}}",
  },
  analytics: {
    ga4: process.env.NEXT_PUBLIC_GA4_ID,
    metrika: process.env.NEXT_PUBLIC_METRIKA_ID,
  },
} as const;
```

**Правило подстановки:** если плейсхолдер не заполнен — выводи на странице явную заглушку `[ЗАПОЛНИТЬ: имя]`, а не выдуманное значение. Мы должны видеть дыры, а не красивую ложь.

### 2.1. Медиа-ассеты

Все изображения кладутся в репозиторий заранее, **до** запуска Claude Code. Он не ищет и не скачивает картинки из интернета — он использует только то, что лежит в папке.

**Портрет Айны уже подготовлен** и лежит в архиве `Айна_ассеты_public.zip`. Распакуй папку `public/` в корень проекта до старта.

```
/public/agent/avatar.jpg      800×800    портрет: шапка, блок «Об эксперте»
/public/agent/avatar.webp     800×800
/public/agent/avatar-400.jpg  400×400    круглая аватарка в шапке
/public/agent/avatar-160.jpg  160×160    мелкие места, источник для favicon
/public/agent/hero.jpg        940×1254   вертикальный кадр для первого экрана
/public/agent/hero.webp       940×1254
/public/agent/hero-705.jpg    705×940    мобильная версия
/public/og-default.jpg       1200×630    карточка для соцсетей и мессенджеров
```

**Чего ещё нет — заглушки с видимой надписью, не выдуманные картинки:**

```
/public/agent/work/1..6.jpg   кадры с объектов для блока на /about
/public/cases/*.jpg           обложки кейсов
/public/logo.svg              если появится; иначе логотип — имя текстом
```

**Ограничение исходника.** Оригинал квадратный, 1254×1254. Вертикальный кадр получился 940×1254 вместо желаемых 1200×1600. Для половины первого экрана и для мобильного этого хватает с запасом. Для полноэкранного героя на большом десктопе — впритык, поэтому **первый экран верстаем в две колонки** (текст слева, портрет справа), а не полноэкранной подложкой. Это же решение лучше и по смыслу: заголовок не тонет в фотографии.

**Цвет фона на портрете** — тёплый тёмный с золотистой подсветкой. Он совпадает с акцентным токеном `--color-accent` из раздела 8, так что палитра сайта строится вокруг этого кадра, а не рядом с ним.

**Отдельно: никаких выдуманных фактов.** Не придумывай суммы сделок, количество объектов, отзывы, имена клиентов и логотипы партнёров. Всё это приходит из базы или из `site.config.ts`. Демо-данные помечай флагом `isDemo: true` и складывай в `prisma/seed.ts`.

### 2.2. Что уже есть в Instagram (@ainona.17) — использовать как источник

Профиль просмотрен, вот что оттуда берём в работу:

| Что | Значение | Как используем |
|---|---|---|
| Шапка профиля | `Айна \| Коммерческая недвижимость` · `Аренда • Продажа • Инвестиции` · `Помещения под бизнес в Алматы` · `Помогаю заехать и зарабатывать` | Готовое позиционирование. Заголовки сайта строим вокруг него, а не вокруг новых формулировок |
| Ключевая фраза | **«Помогаю заехать и зарабатывать»** | Лучше любого копирайта: коротко, глагольно, про деньги клиента. Ставим в первый экран |
| Контакт | WhatsApp `wa.me/7010857717` — единственная ссылка в профиле | После запуска сюда ставится ссылка на сайт с UTM-меткой, иначе трафик из профиля не измеряется |
| Контент | Рилсы с обложками-заголовками, съёмки объектов внутри и снаружи, интерьеры | Исходники рилсов у мобилографа — вероятно, в высоком разрешении. Забрать их до съёмки: это готовый материал для галерей объектов |
| Аватар | Портрет в чёрном пиджаке | Финальный кадр получен отдельно и подготовлен, см. 2.1 |

**Разрыв, который надо обсудить с Айной.** На созвоне главным преимуществом назван «золотой квадрат» — «по золотому квадрату идут только к ней». В шапке профиля этого нет вообще. Либо это преимущество и тогда оно должно быть в первом экране сайта и в шапке Instagram, либо нет — и тогда блок про золотой квадрат на главной не нужен. Решить до вёрстки главной.

## 4. Модель данных

Полная схема Prisma. Реализуй как есть.

```prisma
generator client { provider = "prisma-client-js" }
datasource db { provider = "postgresql"; url = env("DATABASE_URL") }

enum DealType   { RENT SALE BOTH }
enum PropKind   { RETAIL OFFICE WAREHOUSE LAND BUILDING }
enum PropStatus { ACTIVE RESERVED CLOSED HIDDEN }
enum LeadType   { OBJECT SEARCH OWNER CONTACT PRESENTATION }
enum LeadStatus { NEW IN_WORK QUALIFIED REJECTED DEAL }

model Property {
  id            String      @id @default(cuid())
  slug          String      @unique
  externalId    String?     @unique          // id из CRM «РБД» — ключ идемпотентного импорта
  title         String
  kind          PropKind
  dealType      DealType
  status        PropStatus  @default(ACTIVE)

  district      String                        // район Алматы
  address       String?                       // НЕ показывать публично, если isExclusive
  landmark      String?                       // «рядом с ТРЦ ...» — публичный ориентир
  lat           Float?
  lng           Float?

  areaM2        Float
  ceilingM      Float?
  floor         String?                       // "1", "цоколь", "2-3"
  entrance      String?                       // "отдельный вход с улицы"
  powerKw       Float?
  hasWetPoint   Boolean     @default(false)

  priceSale     Decimal?    @db.Decimal(14,2) // ₸, полная стоимость
  priceRentM2   Decimal?    @db.Decimal(10,2) // ₸ за м² в месяц
  priceRentTotal Decimal?   @db.Decimal(14,2) // ₸ в месяц итого
  currency      String      @default("KZT")
  utilitiesIncluded Boolean @default(false)

  isExclusive   Boolean     @default(false)   // закрытый объект: детали только по заявке
  isHot         Boolean     @default(false)   // «горящий вариант»
  isFeatured    Boolean     @default(false)   // на главную

  descriptionMd String      @db.Text
  advantages    String[]                      // 3-5 буллетов
  presentationUrl String?                     // PDF, выдаётся после заявки

  images        PropertyImage[]
  leads         Lead[]

  publishedAt   DateTime?
  createdAt     DateTime    @default(now())
  updatedAt     DateTime    @updatedAt

  @@index([kind, dealType, status])
  @@index([district])
  @@index([isHot, isFeatured])
}

model PropertyImage {
  id         String   @id @default(cuid())
  propertyId String
  property   Property @relation(fields: [propertyId], references: [id], onDelete: Cascade)
  url        String
  alt        String
  width      Int
  height     Int
  order      Int      @default(0)
  @@index([propertyId, order])
}

model Case {
  id          String   @id @default(cuid())
  slug        String   @unique
  title       String                    // «Коммерция в ЖК Терракота»
  kind        PropKind
  dealType    DealType
  district    String?
  areaM2      Float?
  amountLabel String?                   // «500 млн ₸» — строка, не число: иногда «сумма не раскрывается»
  durationLabel String?                 // «1,5 месяца»
  task        String   @db.Text
  solution    String   @db.Text
  result      String   @db.Text
  coverUrl    String?
  isFeatured  Boolean  @default(false)
  order       Int      @default(0)
  createdAt   DateTime @default(now())
}

model Lead {
  id         String     @id @default(cuid())
  type       LeadType
  status     LeadStatus @default(NEW)
  name       String
  phone      String
  comment    String?    @db.Text

  propertyId String?
  property   Property?  @relation(fields: [propertyId], references: [id], onDelete: SetNull)

  // поля брифа на подбор
  briefKind      PropKind?
  briefAreaFrom  Float?
  briefAreaTo    Float?
  briefBudget    String?
  briefDistricts String[]
  briefBusiness  String?

  // атрибуция
  utmSource   String?
  utmMedium   String?
  utmCampaign String?
  utmContent  String?
  pagePath    String?
  referrer    String?

  createdAt  DateTime @default(now())
  @@index([status, createdAt])
}

model Testimonial {
  id       String  @id @default(cuid())
  author   String
  role     String?                       // «собственник помещения на Абая»
  text     String  @db.Text
  order    Int     @default(0)
  isPublic Boolean @default(true)
}

model Setting {
  key   String @id
  value Json
}
```

**Про цены.** Всё в тенге, хранение — `Decimal`, форматирование — через одну функцию `formatPrice()` в `lib/format.ts`: разряды неразрывными пробелами, символ `₸` после числа. Никогда не форматируй цену инлайново в компоненте.

**Про закрытые объекты.** Если `isExclusive = true`, публично отдаются только: тип, район, диапазон площади, ориентир, обобщённая формулировка цены («по запросу»). Точный адрес, полная цена, презентация и фото интерьера — **только после отправки заявки**. Реализуй это на уровне серверного селектора `publicPropertySelect`, а не скрытием в UI: данных не должно быть в HTML-ответе вообще.

## 5. Страницы: структура и контент

Тексты ниже — рабочие. Используй их, подставляя переменные из `site.config.ts`. Там, где нужен факт от заказчика, ставь `[ЗАПОЛНИТЬ: ...]`.

### 5.1. Главная `/`

Порядок блоков строгий — он отражает логику «сначала доверие, потом объекты».

**1. Первый экран**
- H1: `Коммерческая недвижимость в золотом квадрате Алматы`
- Подзаголовок: `Помогаю заехать и зарабатывать. Подбор помещения под бизнес, расчёт окупаемости и сопровождение сделки от первого показа до регистрации.`
- Первая фраза подзаголовка — дословно из шапки её Instagram. Не переписывай её «красивее»: человек, пришедший из профиля, должен узнать формулировку.
- Фото эксперта — `/public/agent/hero.jpg`, справа на десктопе (две колонки, см. 2.1), под текстом на мобильном. `priority`, `sizes` обязательно.
- Две кнопки: `Подобрать объект` (первичная, → `/search`) и `Смотреть объекты` (вторичная, → `/objects`)
- Без слайдеров, без видеофонов, без счётчика обратного отсчёта.

**2. Полоса цифр** — 4 показателя из `site.config.ts`: лет на рынке, объём закрытых сделок, объектов в работе (считается из БД), средний срок сделки.

**3. Горящие варианты** — 3 карточки, `where: { isHot: true, status: ACTIVE }`, сортировка по `updatedAt desc`. Если горящих нет — блок не рендерится вообще (не «скоро появятся»).

**4. Кейсы** — 3 карточки `isFeatured`. Формат карточки: тип объекта → задача одной строкой → результат с цифрой → срок. Ссылка `Все кейсы →`.

**5. «Золотой квадрат»** — текстово-визуальный блок про специализацию. Схематичная карта района инлайн-SVG (не картинка, не Google Maps). Текст: `[ЗАПОЛНИТЬ: 2–3 абзаца про то, почему золотой квадрат и какой там доступ к объектам]`.

**6. Как я работаю** — 4 шага: Заявка и бриф → Подборка объектов с расчётом → Показы и переговоры → Сопровождение сделки и документов. Иконки lucide, без излишеств.

**7. Кому я помогаю** — 3 карточки со ссылками: Инвестору (`/objects`), Арендатору (`/search`), Собственнику (`/owners`). У каждой — своя формулировка боли в одну строку.

**8. Отзывы** — из `Testimonial`. Блок скрывается, если записей меньше двух.

**9. Форма** — компактная: имя, телефон, комментарий (необязательно). Заголовок: `Расскажите, что ищете`. Подпись под кнопкой: `Отвечаю в течение рабочего дня. Обычно быстрее.`

### 5.2. Об эксперте `/about`

Полностью от первого лица, единственного числа. Никаких «мы» и «наша команда».

Блоки: большое фото → история прихода в профессию `[ЗАПОЛНИТЬ]` → специализация и почему именно она → принципы работы (3–4 тезиса) → что входит в сопровождение (включая документы и регистрацию) → фотографии с объектов (сетка 2×3) → отзывы → CTA в WhatsApp.

### 5.3. Кейсы `/cases` и `/cases/[slug]`

Список — сетка карточек с фильтром по типу объекта (клиентский, без перезагрузки).
Детальная — по структуре модели `Case`: задача → решение → результат, плюс блок «Похожие объекты в работе» (3 активных объекта того же `kind`).

Если `amountLabel` пустой — не пиши «сумма не разглашается» крупно; просто не показывай строку.

### 5.4. Каталог `/objects`

**Фильтры** (URL-синхронизированные через `searchParams`, чтобы ссылкой можно было делиться — это рабочий инструмент риелтора):
- Тип сделки: аренда / продажа
- Тип объекта: стрит-ритейл / офис / склад / участок / здание
- Район: мультивыбор из справочника районов Алматы
- Площадь: два поля «от» и «до»
- Бюджет: «от» и «до»
- Чекбоксы: `Только горящие`, `Первая линия` (по флагу `entrance`)
- Сортировка: сначала горящие / по цене / по площади / по дате

**Карточка объекта в списке:** фото 4:3, бейджи (`Горящий`, `Эксклюзив`, `Забронирован`), тип и район, площадь, цена, 2 ключевых преимущества. Клик — на детальную.

Пагинация — «Показать ещё» по 12 штук. Не бесконечный скролл (в нём теряется футер и аналитика).

Пустой результат: текст `По этим параметрам сейчас ничего нет. Опишите задачу — подберу под запрос.` + кнопка на `/search`.

### 5.5. Карточка объекта `/objects/[slug]`

Галерея (клавиатурная навигация, свайп на мобильном) → ключевые параметры таблицей → описание → преимущества буллетами → блок расчёта (**этап 2**, сейчас оставить заглушку-компонент с флагом) → форма `Запросить презентацию` → похожие объекты.

Для эксклюзивных: вместо адреса — ориентир, вместо цены — `Цена по запросу`, поверх галереи одно фото-обложка, остальное закрыто панелью `Детали и презентация — по запросу` с формой.

**Sticky-панель на мобильном**: цена + кнопка `Запросить` фиксируются снизу.

Метаданные: `generateMetadata` с заголовком вида `Стрит-ритейл 120 м², Медеуский район — аренда`, OpenGraph-картинка из первого фото.

### 5.6. Собственникам `/owners`

Отдельная посадочная с другой логикой, чем весь остальной сайт: здесь не выбирают объект, здесь решают, кому доверить свой.

Блоки: заголовок `Сдам или продам ваш объект` → почему через эксперта быстрее, чем самому (прямой ответ на возражение «собственник может сам») → что входит в работу → честно про комиссию: `[ЗАПОЛНИТЬ: формулировка про комиссию]` → кейсы по сдаче → форма `Оценить объект` (имя, телефон, тип объекта, район, площадь).

### 5.7. Подбор объекта `/search`

Бриф-форма в 4 шага (один экран, шаги — визуальные секции, не мастер с перезагрузкой):
1. Что ищете: тип объекта, аренда или покупка
2. Параметры: площадь от-до, бюджет, районы (мультивыбор)
3. Под какой бизнес: свободный текст
4. Контакты: имя, телефон

Прогресс-индикатор. Кнопка активна только при заполненных обязательных полях. После отправки — `/thanks`.

### 5.8. Контакты `/contacts`

Телефон, WhatsApp, Telegram, Instagram, email — все кликабельные. Карта не обязательна. Форма обратной связи. Реквизиты из `site.config.ts`.

### 5.9. Сквозные элементы

- **Шапка:** логотип-имя, меню, телефон, кнопка WhatsApp. На мобильном — бургер, меню на весь экран.
- **Плавающая кнопка WhatsApp** — справа снизу на всех страницах, кроме `/admin`. С `aria-label`, не перекрывает контент и sticky-панель карточки.
- **Подвал:** навигация, контакты, реквизиты, ссылка на политику, год.
- **Хлебные крошки** на всех вложенных страницах.

## 6. Формы и обработка заявок

### Общие правила

Все формы — Server Actions, не API-роуты. Валидация через одну zod-схему на клиенте и сервере.

**Обязательные поля везде — только имя и телефон.** Всё остальное необязательно. Телефон — маска `+7 (___) ___-__-__`, валидация казахстанского формата, но с допуском международных номеров.

**Защита от спама:** honeypot-поле + проверка времени заполнения (меньше 2 секунд = бот) + rate limit по IP (5 отправок за 10 минут). Без капчи — она убивает конверсию.

**Согласие на обработку данных:** чекбокс не нужен, достаточно строки под кнопкой: `Нажимая кнопку, вы соглашаетесь с политикой конфиденциальности` со ссылкой на `/privacy`.

### Что происходит после отправки

Последовательность в Server Action:

1. Валидация zod. При ошибке — вернуть ошибки полей, ничего не отправлять.
2. Собрать UTM-метки из cookie (см. ниже) + `pagePath` + `referrer`.
3. Записать `Lead` в БД. **Это критический шаг: если он упал — вернуть пользователю ошибку.**
4. Отправить уведомление в Telegram. **Не критический: ошибка логируется, пользователю не показывается.**
5. Добавить строку в Google Sheets, если настроено. Тоже не критический.
6. Отправить событие в аналитику (`lead_submit` с параметром типа заявки).
7. Редирект на `/thanks?type=...`.

Шаги 4 и 5 не должны блокировать ответ дольше 3 секунд — оборачивай в `Promise.allSettled` с таймаутом.

### Telegram-уведомление

`lib/notify/telegram.ts`, Bot API `sendMessage`, `parse_mode: HTML`. Формат:

```
🔔 Новая заявка: подбор объекта

Имя: Айгуль
Телефон: +7 701 000 00 00
Объект: Стрит-ритейл 120 м², Медеуский  ← если есть
Комментарий: нужно под кофейню

Источник: instagram / cpc / autumn_retail
Страница: /objects/street-retail-abaya-120
```

Телефон отдельной строкой, чтобы копировался одним тапом. Эмодзи допустимы только здесь — это служебное сообщение, не интерфейс.

### Google Sheets

`lib/notify/sheets.ts`, service account, `spreadsheets.values.append`. Колонки: дата, тип заявки, имя, телефон, объект, комментарий, UTM-источник, UTM-кампания, страница. Если переменные окружения не заданы — модуль тихо отключается, никаких ошибок сборки.

### UTM-атрибуция

Middleware читает `utm_*` из query при первом заходе и кладёт в cookie на 90 дней (first-touch, не перезаписывать при повторных визитах с другими метками — иначе потеряем первый источник). Форма читает cookie. Это единственный способ понять, что приносит заявки, — офлайн-каналы заказчика сейчас не измеряются вообще.

## 7. Админ-панель `/admin`

Отдельный layout, без шапки и футера публичного сайта. Интерфейс на русском.

### Доступ

Один администратор. Auth.js, Credentials provider. `ADMIN_EMAIL` и `ADMIN_PASSWORD_HASH` (bcrypt) в переменных окружения. Middleware защищает всё под `/admin`, кроме `/admin/login`. Сессия — JWT, 7 дней.

Никакой регистрации, восстановления пароля и списка пользователей.

### `/admin/objects`

- Таблица: фото, название, тип, район, площадь, цена, статус, флаги, дата. Поиск по названию, фильтр по статусу.
- Быстрые действия прямо из таблицы: переключить `isHot`, `isFeatured`, сменить статус. Без захода в карточку.
- Форма создания/редактирования — все поля модели, сгруппированы: Основное / Расположение / Параметры / Цена / Тексты / Фото / Флаги.
- **Загрузка фото:** drag-n-drop, множественная, превью, перетаскивание для сортировки, удаление. При загрузке — ресайз до ширины 2000px и конвертация в WebP на сервере, оригинал не хранить.
- `slug` генерируется из названия транслитерацией, с возможностью ручной правки, с проверкой уникальности.
- Автосохранение черновика в `localStorage` — чтобы не терять текст при случайном закрытии.

### `/admin/cases` — то же самое, проще: поля модели `Case`, одна обложка.

### `/admin/leads`

Таблица заявок: дата, тип, имя, телефон, объект, источник, статус. Фильтр по статусу и датам. Смена статуса из списка. Экспорт в CSV. Новые заявки подсвечены.

### `/admin/settings`

Редактирование через модель `Setting`: тексты первого экрана, четыре цифры в полосе показателей, контакты, текст блока «золотой квадрат», отзывы (`Testimonial` — отдельная простая таблица).

### Импорт из CRM «РБД»

Скрипт `scripts/import-crm.ts`, запуск `npm run import -- ./data/export.csv`.

- Маппинг колонок — в отдельном файле `scripts/crm-mapping.ts` с подробными комментариями. **Реальный формат выгрузки неизвестен**, поэтому: сделай маппинг под гипотетические колонки, вынеси его в одно место и напиши в README, что этот файл правится под фактическую выгрузку.
- Идемпотентность по `externalId`: существующие обновляются, новые создаются.
- **Никогда не удаляй объекты автоматически.** Отсутствующие в выгрузке — переводи в статус `HIDDEN` и выводи список в консоль.
- Режим `--dry-run`: показать, что изменится, ничего не писать.
- Отчёт в конце: создано / обновлено / скрыто / ошибок.

## 8. Дизайн

### Направление

Сдержанная премиальность. Ориентир — сайты частных консультантов по инвестициям, не сайты агентств недвижимости. Много воздуха, крупная типографика, мало цвета, фотография работает вместо украшений.

**Чего не делать:** стоковых фото небоскрёбов и рукопожатий, градиентов на кнопках, теней-свечений, анимаций появления на каждом блоке, каруселей, счётчиков-«крутилок», иконок в кружочках с градиентом.

### Токены

В `globals.css` через `@theme`. Ни одного hex-значения в компонентах.

```css
--color-ink:        #12161C;   /* основной текст, почти чёрный */
--color-ink-muted:  #5A6674;   /* вторичный текст */
--color-line:       #E3E7EC;   /* границы */
--color-surface:    #FFFFFF;
--color-surface-2:  #F6F8FA;   /* фон чередующихся секций */
--color-accent:     #8A6A3B;   /* приглушённое золото — специализация «золотой квадрат» */
--color-accent-ink: #6B5230;   /* accent для текста, контраст ≥ 4.5:1 на белом */
--color-hot:        #B4442F;   /* бейдж «горящий» */
--color-success:    #2F6B4F;
```

Проверь контрасты по WCAG AA. Акцентный цвет на кнопке — с белым текстом, контраст ≥ 4.5:1.

### Типографика

- Заголовки и текст — один гротеск с полноценной кириллицей: **Inter** или **Manrope** через `next/font/google`, подмножество `cyrillic`, `display: swap`.
- Шкала: h1 `clamp(2rem, 5vw, 3.25rem)`, h2 `clamp(1.5rem, 3vw, 2.25rem)`, body `1rem/1.6`.
- Цифры в таблицах и ценах — `font-variant-numeric: tabular-nums`.
- Переносы: `hyphens: auto` не включать для русского — некрасиво ломает слова.

### Сетка и ритм

Контейнер `max-width: 1200px`, боковые отступы `16px` на мобильном, `24px` от 640px, `40px` от 1024px. Вертикальный ритм секций: `64px` мобильный, `96px` десктоп. Радиус скругления — один на весь сайт, `8px`. Тени — максимум две: карточка и модалка.

### Состояния — обязательны для каждого интерактивного элемента

Покой, наведение, фокус (видимый `focus-visible`, не `outline: none`), нажатие, загрузка, отключено. Для списков — скелетоны, не спиннеры.

## 9. Производительность, доступность, SEO

### Производительность — целевые значения

Lighthouse mobile: Performance ≥ 90, Accessibility ≥ 95, Best Practices ≥ 95, SEO ≥ 95. LCP < 2.5s, CLS < 0.1, INP < 200ms на эмуляции Moto G Power / 4G.

- Все изображения через `next/image`, с обязательными `width`/`height` или `fill` + `sizes`. Никаких `<img>`.
- Первое фото на главной — `priority`, остальные ленивые.
- Шрифты — `next/font`, без внешних запросов к Google на рантайме.
- Каталог — серверный рендер с кешированием, фильтрация на сервере, не подгрузка всех 70 объектов на клиент.
- Ноль блокирующих сторонних скриптов в `<head>`. Счётчики аналитики — `next/script` со стратегией `afterInteractive`.

### Доступность

Семантические теги, один `h1` на страницу, логичная иерархия заголовков. Вся навигация с клавиатуры. Галерея — стрелки и Escape. Модалки — focus trap и возврат фокуса. Все изображения объектов — осмысленный `alt` вида `Стрит-ритейл 120 м² на Абая, витринное остекление`. Формы — `<label>` для каждого поля, ошибки связаны через `aria-describedby`.

### SEO

- `generateMetadata` на каждой странице, уникальные title и description.
- JSON-LD: `RealEstateAgent` на главной, `Product` + `Offer` на карточках объектов, `BreadcrumbList` на вложенных.
- `sitemap.ts` и `robots.ts` — динамические, объекты из БД.
- Канонические URL. Фильтры каталога — `noindex` для комбинаций с параметрами, индексируется только `/objects`.
- OpenGraph-картинки: статичная для страниц, динамическая через `opengraph-image.tsx` для объектов.
- `lang="ru"`, архитектура URL готова к `kk` (`/kk/...`) без переделки.

## 11. Этапы реализации

Каждый этап заканчивается рабочим состоянием: проект собирается, страницы открываются, ошибок в консоли нет.

**Этап 2. Заявки**
Server Actions, zod-схемы, антиспам, UTM через middleware, запись в БД, Telegram, Google Sheets, страница `/thanks`, цели аналитики.

**Этап 3. Админка**
Auth.js, защита роутов, CRUD объектов с загрузкой фото, CRUD кейсов, список заявок с экспортом, настройки, отзывы.

Lighthouse и доведение до целевых значений. SEO-разметка, sitemap, robots, OG-картинки. Проверка доступности с клавиатуры. Страницы 404 и 500. README: установка, запуск, деплой, как править контент, как импортировать выгрузку.

### Что НЕ делать в этом заходе

Калькулятор окупаемости, аналитику по районам, блог, раздел партнёров, каталог бизнес-центров, казахскую версию, личный кабинет собственника, интеграцию с krisha.kz, онлайн-оплату, чат-бота.

## 13. Как задавать вопросы по ходу

Если в ТЗ чего-то не хватает:

1. **Есть очевидное решение** — прими его, реализуй, запиши в `DECISIONS.md` одной строкой.
2. **Решение меняет архитектуру или объём работ** — остановись и спроси. Не додумывай.
3. **Не хватает фактического содержания** (сумма, имя, текст «о себе») — поставь `[ЗАПОЛНИТЬ: что именно]` и собери все такие места в конце `DECISIONS.md` списком.

Никогда не заменяй недостающий факт правдоподобным вымыслом. Пустое место видно и исправимо, выдуманная цифра — нет.
