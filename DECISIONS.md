Формат: одно решение — одна строка. Правило из SPEC.md, раздел 13: очевидное решение принимаем и записываем;
меняющее архитектуру — спрашиваем; недостающий факт — ставим `[ЗАПОЛНИТЬ]` и собираем в конце.

## Стек и версии (проверены на момент сборки, 15.09.2026)

- Next.js 16.3.5, React 19.2, Tailwind CSS 4.3, Prisma 7.10 (стабильная; 8.x — RC, не берём), next-auth 5.0.0-beta.32 (v5 всё ещё beta — это единственная ветка «Auth.js v5», как требует ТЗ), next-intl 4.14, zod 4.6, react-hook-form 7.88, lucide-react 1.46, sharp 0.35, @vercel/blob 2.8, TypeScript 5.9.
- Prisma 7 не поддерживает `prisma-client-js` и `url` в блоке `datasource`: схема из ТЗ перенесена как есть, но генератор — `prisma-client` с `output = "../lib/generated/prisma"`, а `DATABASE_URL` задаётся в `prisma.config.ts`. Enum'ы из ТЗ в одну строку Prisma не парсит — развёрнуты построчно, значения те же.
- Prisma 7 требует driver adapter: используется `@prisma/adapter-pg` (`lib/db.ts`).
- В Next 16 `middleware.ts` переименован в `proxy.ts` — файл называется `proxy.ts`, логика та же (UTM-cookie, защита `/admin`, маршрутизация локалей).
- `next lint` удалён в Next 16 — линт через `eslint .` (`npm run lint`).
- Кеширование каталога: `unstable_cache` с тегами (`lib/cache.ts`) + ISR `revalidate = 60` на публичных страницах. `use cache`/Cache Components не включали — это меняет модель рендеринга всего приложения. Инвалидация из админки — `updateTag` + `revalidatePath("/", "layout")`.
- Локаль: структура `app/[locale]/…`, `localePrefix: "as-needed"` — `ru` без префикса, `kk` включится как `/kk/...` без переделки (добавить в `site.site.locales` и заполнить `messages/kk.json`; недостающие ключи подхватываются из `ru` через deep-merge в `i18n/request.ts`). Локаль читается через `next/root-params` (Next 16.3+).
- Админка живёт внутри `[locale]` (`app/[locale]/admin`), но со своим layout без шапки/подвала сайта — так у неё те же словари и та же маршрутизация; URL остаётся `/admin/...`.

## Инфраструктура разработки

- Локальный PostgreSQL для разработки — пакет `embedded-postgres` (`npm run db:local`, данные в `.pgdata/`), чтобы не ставить сервер в систему. Прод — Neon/Supabase по `DATABASE_URL`.
- Хранилище файлов (`lib/storage.ts`): при отсутствии `BLOB_READ_WRITE_TOKEN` в development фото пишутся в `public/uploads/` — чтобы загрузку и сортировку можно было проверить без аккаунта Vercel. В production без токена загрузка отключена с понятным сообщением в админке.
- Google Sheets: вместо тяжёлого `googleapis` — прямой вызов REST `values.append` с JWT сервисного аккаунта, подписанным через `node:crypto`.
- Rate limit заявок (5/10 мин) хранится в памяти процесса; на Vercel каждый инстанс считает отдельно. Для MVP достаточно, замена на Redis не меняет сигнатуру `checkRateLimit`.
- Пароль админа — bcrypt-хеш в `ADMIN_PASSWORD_HASH`. Next.js раскрывает `$ИМЯ` в `.env`-файлах (кавычки не спасают), поэтому в `.env.local` каждый `$` хеша экранируется как `\$`; `npm run hash-password` печатает готовую строку. В панели Vercel хеш вставляется как есть.

## Производительность

- Формы заявок на главной, в контактах и на карточке объекта гидрируются отложенно (`LeadFormDeferred` → `LeadFormLazy`): сервер отдаёт статичную копию формы, а react-hook-form + zod подгружаются, когда форма в 600px от экрана или пользователь коснулся поля (введённое переносится, фокус возвращается). Это убирает ~90 KB JS из критического пути главной.
- Схемы заявок (`lib/validation/lead.ts`) написаны на `zod/mini` — тот же zod 4 и та же единая схема клиент/сервер, но tree-shakeable: в браузер уезжает ~25 KB вместо ~90 KB gzip у классического `zod`. Админские схемы (`lib/validation/admin.ts`) остаются на классическом zod — их бандл на публичные страницы не попадает.
- Клиентские компоненты публичных страниц (фильтры каталога, галерея, фильтр кейсов, строка согласия) получают все подписи пропсами с сервера и не вызывают `useTranslations` — так на публичных страницах нет клиентского рантайма форматирования сообщений. Провайдер словарей отдаёт клиенту только `common`/`enums`/`forms`/`search` (`i18n/messages.ts`); админка — `common`/`enums`/`admin`.
- Портрет на первом экране — `priority` + `fetchPriority="high"`; `overflow-wrap: anywhere` с body убран (дорогой layout), `text-wrap: balance` только на h1/h2.
- Lighthouse гонялся локально через headless Edge (`CHROME_PATH=…msedge.exe npx lighthouse …`), результаты — в README, раздел «Проверки качества».

- Hex-цвета вне `globals.css` есть только в двух местах, где CSS-переменные недоступны: `app/global-error.tsx` (ошибка корневого layout рендерится без стилей) и `opengraph-image.tsx` (satori не читает CSS). Значения те же, что у токенов.

## Продуктовые решения

- Закрытые объекты (`isExclusive`): факт отправки заявки по объекту хранится в подписанной httpOnly-cookie (`lib/unlock.ts`). После заявки «Запросить презентацию» страница объекта показывает адрес, цену, все фото и ссылку на презентацию — данных нет в HTML до заявки. Описание и преимущества остаются видимыми (они пишутся автором с учётом закрытости).
- Фильтр «Первая линия» — по флагу `entrance`: объекты с заполненным описанием входа (в модели нет отдельного булева поля).
- Фильтр «Бюджет»: для аренды — по `priceRentTotal`, для продажи — по `priceSale`, без выбранного типа сделки — по любому из двух.
- Сортировка «по цене» зависит от выбранного типа сделки (аренда → `priceRentTotal`, продажа → `priceSale`), объекты без цены — в конце.
- Четвёртый показатель полосы цифр «средний срок сделки» добавлен в `site.config.ts` как `agent.avgDealDuration` (в шаблоне ТЗ поля не было). Все четыре можно переопределить в `/admin/settings`.
- Событие аналитики `lead_submit` отправляется со страницы `/thanks` (клиентские счётчики GA4/Метрика недоступны из Server Action); тип заявки передаётся параметром `lead_type`.
- Демо-данные помечены `isDemo: true` в `prisma/seed.ts` и явно подписаны «Демо» в заголовках. Удаление: `npm run db:seed -- --clean`.
- Портрет: `/agent/hero.jpg` (940×1254) используется одним `next/image` с `sizes` — файл `hero-705.jpg` того же кадра не нужен для art direction, оптимизатор сам отдаёт нужную ширину.
- Динамическая OG-картинка объекта рендерит текст шрифтом Inter SemiBold (OFL), файл `lib/og/Inter-SemiBold.ttf` — satori не поддерживает woff2 и не содержит кириллицы.
- В `/admin` без сессии — редирект на `/admin/login`; `/admin` с сессией — на `/admin/objects` (в карте сайта `/admin` = «Вход»).
- Кнопка бриф-формы `/search` активна только при валидных имени и телефоне (обязательные поля); остальные шаги необязательны.
- Иконки бренда (Instagram) в lucide-react 1.x удалены — для Instagram используется нейтральная иконка `Camera`.
- «Золотой квадрат»: реализовано по ТЗ (H1 + блок на главной). Границы на схеме условные: подписан только проспект Абая как южная граница, точные границы — открытый вопрос (см. ниже).
